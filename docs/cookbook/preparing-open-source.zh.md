# 操作指南：准备公开源码

[English](preparing-open-source.md) | 中文

本流程导出公开分支已审核的工作区源码。分支仍共享原有 Git 历史；对外发布应从导出目录建立新仓库，不直接公开原私有仓库。

## 1. 检查源码

安装锁定的开发依赖，并运行改动相关测试。平台签名设置、模型凭据、会话和构建缓存保留在本地。[ERP 集成](../../integrations/erp/README.zh.md) 提供公开桌面入口，默认不附带行业模板。

```sh
node --test scripts/export-open-source.spec.mjs
node scripts/export-open-source.mjs --check
```

检查覆盖受 Git 跟踪的源码及已审核的新增文件，排除私有集成目录、本地环境文件、签名密钥、缓存、生成的运行时库和 Git 元数据；保留构建与文档检查依赖的维护规范及上游参考记录。未知未跟踪文件、链接或已知客户品牌标记会中止导出；诊断只显示路径，不输出命中内容。这是发行过滤，不能证明每份文件都安全；发布前仍需审核新增资源及客户专属改动。

## 2. 导出新目录

```sh
node scripts/export-open-source.mjs --output dist/public-source
```

输出目录必须尚不存在。导出器先写临时目录，将文件 SHA-256 记录到 `source-manifest.json`，最后重命名为目标目录；失败不会留下最终目录。当前源码修改会导出，仓库历史、本地备份和已忽略的设置不会导出。该命令不创建远程仓库，不提交、上传或操作数据库。

## 3. 验证公开构建

将源码目录复制到干净环境，安装锁定依赖，运行相应构建及平台打包检查。确认默认名称、图标、欢迎页和安装页通用，再使用套件配置重复检查；本地自动化测试不能替代这些安装包检查。发行安装包前配置自己的应用 ID、服务地址、签名凭据和更新服务，源码导出不会转移本机设置。
