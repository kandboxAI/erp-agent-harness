# @deepseek-ai/dsh-client-ui-ai-control

[English](README.md) | 中文

## 摘要

用户可针对已完成的Chat回答预览并编辑问题和回答片段，然后提交到企业控制中心；也可查看该消息最新的处理进度和人工回复。反馈权限与处置由ERP管理；ERP桌面仅显示企业反馈，普通配置保留原生反馈。

<a id="use-this-package"></a>
## 使用本包

ERP桌面配置通过insert新增本插件条目，并在自身覆盖层停用原生赞踩界面、消息反馈服务和原生/feedback处理器；普通Web及非ERP配置仍保留原生反馈。本插件无可配置字段。桌面连接器提供已认证的反馈和图片通道；普通Web配置默认不挂载本包，显式挂载时须提供企业传输通道。

ERP租户须开通ai_control，并向用户授予ai_control:feedback:submit及ai_control:feedback:mine；运营在ERP使用ai_control:feedback:handle及其配置的数据范围。知识库为可选能力；租户迁移和真实桌面验收仍由部署流程完成。

已完成回答下方的小型踩图标打开该回答的ERP确认弹窗；客户端/feedback命令针对最近一条已完成回答打开同一会话弹窗，不提交或唤醒Agent。没有已完成回答时，弹窗提示缺少反馈对象。确认内容包含问题、所选回答、分类、说明及主动选择或粘贴的图片，可选择请求人工回复。在打开的弹窗内选择图片或按Ctrl+V粘贴，缩略图支持预览与移除；最多6张JPG、PNG、WebP图片，每张2 MB。选择或粘贴时开始上传，上传完成后才允许提交反馈。聊天原有附件不会自动附带。响应未确认时，未修改内容的重试沿用提交编号，关闭再打开弹窗也保留；修改失败草稿后使用新编号。请求失败时保留草稿。提交失败和暂无反馈的查询结果显示在底部操作按钮旁，不随表单字段滚动。

当前打开会话中，不含工具调用的业务文字回答落盘后，插件即通过现有ERP模型网关独立复核本轮用户请求和回答，在自动整理岗位记忆之前发起；记忆维护回答不触发复核。未完成结论必须逐段引用回答中的证据，省略号连接的每段引文仍须按顺序存在于原文。插件先询问是否反馈，提供“填写反馈”和“暂不反馈”；选择填写后才打开在补充说明中预填原因、可编辑的“没有解决”草稿；提交仅包含反馈接口声明的字段，不自动提交。未完成及检查失败的结果在有反馈或重试操作时显示可关闭的弹窗；需要澄清、无法判断（包括缺少可复核文字）时不展示提示，只有“暂不反馈”的弹窗也不展示；检查中以输入框上方的紧凑无边框行展示转圈图标和状态文字；检查失败时显示安全的错误类别，并提供“重试检查”和“手动反馈”。已有草稿保留至用户明确选择打开。历史加载、重连、已取消轮次及关闭建议均不会重复检查；新轮次开始后不再展示上一轮尚未返回的复核建议。

进度查询按当前ERP用户和目标消息定位最新反馈，不在本地存储反馈凭证或令牌。ERP令牌保留在桌面主进程。

提交结果以独立的“我的反馈”和“人工回复”区域展示，状态和反馈编号位于顶部。本次成功提交的说明可直接查看，问题和回答片段可展开；没有人工回复时显示明确提示。查询到其他反馈编号时不展示当前草稿，避免将未提交内容误当作原反馈。

<a id="understand-the-implementation"></a>
## 理解实现

插件拥有复核提示词、结果解析、实时轮次监听和弹窗规则；ERP校验反馈权限，并承担模型鉴权、脱敏、配额和用量记录。插件在conversation.chat.assistant-actions注册图标，在conversation.input.overlay注册共用弹窗，并提供客户端/feedback命令；是否加载由配置条目决定，不再依赖额外的全局启动标记。[message.ts](src/client/message.ts)读取已加载的Chat投影，[Feedback.tsx](src/client/Feedback.tsx)展示可编辑片段和提交确认。[桌面连接器](../../../apps/desktop-host/src/erp-desktop-tools.ts)转发固定的ERP反馈请求。Electron主进程申请签名上传地址并直接向存储上传图片，不向存储转发ERP令牌。确认提交只发送文件ID，ERP在同一事务中绑定图片与反馈并控制附件访问；持久化处置记录由ERP维护。

<a id="model-experience"></a>
## 模型体验

符合条件的新回答会增加一次独立模型调用，输出最多1024 tokens；输入仅为本轮用户请求和最终回答，每段最多2万字符。不附带图片、推理、工具结果和此前轮次；不唤醒原会话Agent、不改变其请求前缀、不提交反馈或记录原生反馈遥测。复核沿用ERP网关的配额与用量记录。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- 入口针对Chat每轮最终回答；流式、已中断及轨迹视图消息没有企业反馈入口。
- 之前的问题未加载时片段为空；长文本截取为弹窗可见且可编辑的最多2万字符片段，不包含推理、聊天原有附件、工具结果或其他消息；只有用户主动选择或粘贴到表单的图片会附带。
- 完成度复核只覆盖会话挂载期间新发生、正常结束的轮次；缺失或过长文字不复核，不能仅靠文字证明实际业务结果。复核结果不跨应用重启持久化。
- 草稿不是离线队列，关闭应用后不保留；普通赞踩不会创建ERP问题单。
- 查进度展示ERP回复；未实现原会话回复注入和持续人工接管。

<a id="dev-note"></a>
### 开发备注

Desktop Host 引用 `tsconfig.host.json` 编译复核请求与结论解析器。Client 聚合项目引用 `tsconfig.client.json`；包根目录的配置仅组织子项目。Host 编译完成后，Typert 才生成浏览器代码使用的 Remote 声明。

定向组件测试通过生产Session插槽渲染器覆盖所选消息片段、提交确认、未确认提交的重试及进度展示。根客户端聚合项目引用本包，并在桌面构建时检查这些测试的类型。真实浏览器回归使用录制会话，验证无全局启动标记时的图标显示、图片粘贴、选择、移除、确认后向模拟ERP接口提交，以及/feedback打开同一弹窗。ERP租户和完整桌面安装包验收需要目标环境。
